🔎 What is Playwright?

  • Open-source browser automation library by Microsoft
  • Built for reliable, fast end-to-end testing
  • Cross-browser: Chromium, Firefox, WebKit
  • Multi-language: JS, TypeScript, Python, Java, .NET
  • Handles SPAs, iframes, shadow DOM, network, files
import { test, expect } from '@playwright/test'; test('page has title', async ({ page }) => { await page.goto('https://playwright.dev'); await expect(page) .toHaveTitle(/Playwright/); });

# Scaffold a new project (recommended) npm init playwright@latest # Or add to an existing project npm install -D @playwright/test npx playwright install

🎯 Element Locators

  • getByRole — page.getByRole('button', { name: 'Submit' })
  • getByText — page.getByText('Welcome back')
  • getByLabel — page.getByLabel('Email address')
  • getByPlaceholder — page.getByPlaceholder('Search…')
  • getByAltText — page.getByAltText('Company logo')
  • getByTestId — page.getByTestId('submit-btn')
  • locator — page.locator('.card').first() (CSS / XPath fallback)

💡 Tip: Prefer User-Facing Locators

// ❌ Brittle — breaks on any CSS refactor page.locator('body > div > section > button:nth-child(2)') // ⚠️ Still coupled to implementation details page.getByTestId('login-btn') // ✅ Best — mirrors how real users see the page page.getByRole('button', { name: 'Log in' }) page.getByLabel('Email address')
  • Role/label selectors simultaneously test accessibility
  • They survive redesigns; CSS selectors often don't
  • Fall back to getByTestId only when no semantic option exists

⏱️ Auto-Waiting & Assertions

// Playwright waits automatically — no manual sleep() needed await page.getByRole('button', { name: 'Submit' }).click(); await page.getByLabel('Email').fill('alice@example.com'); // Web-first assertions — retries until condition is met (5 s default) await expect(page.getByText('Welcome, Alice!')).toBeVisible(); await expect(page).toHaveURL(/dashboard/); await expect(page.getByRole('listitem')).toHaveCount(5);
  • Actions wait: attached, visible, stable, enabled, not-obscured
  • Assertions retry: no need to poll manually

💡 Tip: Avoid These Anti-Patterns

// ❌ Never hardcode delays — root cause of flakiness await page.waitForTimeout(3000); // ❌ Avoid — waits for network quiet, not your element await page.waitForLoadState('networkidle'); // ✅ Wait for exactly what the test cares about await expect(page.getByText('Results loaded')).toBeVisible(); await expect(page.locator('.data-row')).toHaveCount(10);

⚠️ Flaky tests are almost always caused by wrong wait strategies — trust Playwright's auto-waiting!

📝 Working with Forms

// Fill text fields await page.getByLabel('Email').fill('alice@example.com'); await page.getByLabel('Password').fill('s3cret!'); // Select a dropdown option await page.getByLabel('Country').selectOption('US'); // Toggle a checkbox await page.getByLabel('Remember me').check(); // Upload a file await page.getByLabel('Avatar').setInputFiles('./photo.png'); // Submit await page.getByRole('button', { name: 'Sign in' }).click();

💬 Dialogs & Popups

// Accept (or dismiss) a native browser dialog page.once('dialog', dialog => dialog.accept()); // Capture a new tab opened by a link click const [newPage] = await Promise.all([ context.waitForEvent('page'), page.getByRole('link', { name: 'Open report' }).click(), ]); await newPage.waitForLoadState(); // Download a file const download = await page.waitForEvent('download'); await download.saveAs('./invoice.pdf');

🌐 Network Interception

// Block images to speed up tests await page.route('**/*.{png,jpg,gif,svg,webp}', r => r.abort()); // Spy on API responses page.on('response', res => { if (res.url().includes('/api/')) console.log(res.status(), res.url()); }); // Wait for a specific API call triggered by a user action const resPromise = page.waitForResponse('**/api/users'); await page.getByRole('button', { name: 'Load users' }).click(); const res = await resPromise; console.log(await res.json());

💡 Tip: Mock API Responses

// Use route.fulfill() to return fake data (not abort!) await page.route('**/api/users', async route => { await route.fulfill({ status: 200, contentType: 'application/json', body: JSON.stringify([ { id: 1, name: 'Alice' }, { id: 2, name: 'Bob' }, ]), }); });
  • Isolate tests from flaky backends — deterministic results every time
  • Easily simulate errors: set status: 500 or status: 401
  • Can also use route.fetch() then modify the real response

🏗️ Page Object Model (POM)

// pages/LoginPage.ts export class LoginPage { constructor(private page: Page) {} emailInput = this.page.getByLabel('Email'); passwordInput = this.page.getByLabel('Password'); async goto() { await this.page.goto('/login'); } async login(email: string, pass: string) { await this.emailInput.fill(email); await this.passwordInput.fill(pass); await this.page.getByRole('button', { name: 'Log in' }).click(); } } // In your test: const loginPage = new LoginPage(page); await loginPage.login('alice@test.com', 's3cret');

🔧 Playwright Fixtures

// fixtures.ts — extend test with custom fixtures import { test as base } from '@playwright/test'; import { LoginPage } from './pages/LoginPage'; export const test = base.extend<{ loginPage: LoginPage }>({ loginPage: async ({ page }, use) => { const lp = new LoginPage(page); await lp.goto(); await use(lp); // ← provide fixture to test // optional teardown runs here after each test }, }); // Tests receive loginPage automatically — zero boilerplate test('login works', async ({ loginPage }) => { await loginPage.login('alice', 'pass'); });

📸 Screenshots, Video & Traces

// Take a full-page screenshot any time await page.screenshot({ path: 'shot.png', fullPage: true }); // Screenshot a single element await page.locator('.chart').screenshot({ path: 'chart.png' }); // playwright.config.ts — auto-capture on failure use: { screenshot: 'only-on-failure', video: 'retain-on-failure', trace: 'retain-on-failure', }

🎬 Test Codegen

# Record in desktop Chrome npx playwright codegen https://myapp.dev # Record in mobile emulation npx playwright codegen --device="iPhone 15" https://myapp.dev # Save directly to a file npx playwright codegen -o tests/my-flow.spec.ts https://myapp.dev

  • Excellent starting point — then refine with Page Objects & assertions

💡 Tip: Organize Tests Well

test.describe('Login', () => { test.beforeEach(async ({ page }) => { await page.goto('/login'); // shared setup — DRY }); test('valid credentials → dashboard', async ({ page }) => { /*…*/ }); test('wrong password → error banner', async ({ page }) => { /*…*/ }); test('empty form → field errors', async ({ page }) => { /*…*/ }); });
  • Each test must be independent — never share state between tests
  • Use test.only / test.skip during development
  • Group related scenarios; nest describe blocks for sub-features

🐛 Debugging Tests

# Open the Playwright Inspector (step-through debugger) PWDEBUG=1 npx playwright test # Run headed with slow motion (500 ms per action) npx playwright test --headed --slow-mo=500 # Replay a trace recorded from a CI failure npx playwright show-trace trace.zip
// Pause inside a test to inspect live — opens Inspector await page.pause();
  • Inspector: step through, evaluate locators, explore the DOM live
  • Trace Viewer: full timeline — actions, network, screenshots, console

🚀 CI/CD Integration

# .github/workflows/playwright.yml - name: Install dependencies run: npm ci - name: Install Playwright browsers run: npx playwright install --with-deps - name: Run tests run: npx playwright test - name: Upload HTML report uses: actions/upload-artifact@v4 with: name: playwright-report path: playwright-report/
  • Tests run in parallel across workers by default (set workers in config)
  • Shard across multiple CI machines: --shard=1/4

✅ Best Practices

  • ✅ Use getByRole / getByLabel selectors
  • ✅ Structure with describe + beforeEach
  • ✅ Apply Page Object Model for scale
  • ✅ Leverage fixtures for setup/teardown
  • ✅ Never use sleep() — trust auto-waiting
  • ✅ Mock APIs with route.fulfill()
  • ✅ Enable trace: 'retain-on-failure'
  • ✅ Keep tests independent & focused
