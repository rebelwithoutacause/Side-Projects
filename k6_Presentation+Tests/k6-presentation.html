Introduction

What is k6?

k6 is an open-source performance testing tool built for developers and QA engineers. You write tests in JavaScript, run them from the terminal, and get detailed metrics about how your system behaves under load.

🟢

Open Source

Free, actively maintained by Grafana Labs with a huge community

📝

JavaScript

Write tests in JS — no new language or framework to learn

⚙️

CLI First

Runs from terminal, CI pipelines, Docker, or GitHub Actions

Introduction

Why Use k6?

  • Find problems before users do — catch slow endpoints and bottlenecks in dev before they reach production
  • Know your limits — discover exactly how many users your system can handle
  • CI/CD ready — automatically fails builds when performance degrades
  • Realistic simulation — virtual users, think time, chained requests
  • Clear metrics — p95, p99, req/s, error rate all in one summary

Making HTTP Requests

requests.js 
// GET request
const res = http.get('https://dummyjson.com/users/1');

// POST with JSON body + headers
const res = http.post(
  'https://dummyjson.com/auth/login',
  JSON.stringify({ username: 'emilys', password: 'emilyspass' }),
  { headers: { 'Content-Type': 'application/json' } }
);

// GET with Bearer token (authenticated)
const res = http.get('https://dummyjson.com/auth/me', {
  headers: { 'Authorization': `Bearer ${token}` },
});
Core Concepts

The Response Object

PropertyTypeWhat it contains
res.statusnumberHTTP status code — 200, 201, 404, 500...
res.bodystringRaw response body as a string
res.json()objectResponse body parsed into a JavaScript object
res.timings.durationnumberTotal request time in milliseconds
res.headersobjectAll response headers as key-value pairs
Always check res.status before reading res.json() — the body may be empty or an error page on failure.
Core Concepts

Checks — Assertions

checks.js 
import { check } from 'k6';

check(res, {
  'status is 200':      (r) => r.status === 200,
  'has access token':   (r) => r.json().accessToken,
  'response under 500ms':(r) => r.timings.duration < 500,
  'body not empty':     (r) => r.body.length > 0,
});
  • Do not stop the test — they only record pass/fail counts
  • Returns true → pass
  • Returns false → fail (still continues)
  • Results appear in the final summary
Core Concepts

Thresholds — Pass / Fail the Whole Test

options — thresholds 
export const options = {
  thresholds: {
    http_req_failed:   ['rate<0.01'],              // <1% errors
    http_req_duration: ['p(95)<500', 'p(99)<1000'], // speed SLAs
    checks:            ['rate>0.95'],              // >95% checks pass
  },
};
A breached threshold makes k6 exit with a non-zero code — this automatically fails CI/CD pipelines without any extra configuration.

Core Concepts

Sleep & Stages

Sleep — Think Time

// Fixed pause
sleep(1);

// Random 0–3s (realistic)
sleep(Math.random() * 3);

Simulates the time a real user spends reading, thinking, or filling a form between actions.

Stages — Traffic Shape

stages: [
  { duration: '2m', target: 50 }, // ramp ↑
  { duration: '5m', target: 50 }, // hold
  { duration: '2m', target: 0  }, // ramp ↓
]

target = VUs at end of stage. k6 smoothly ramps between them.

Core Concepts

Chaining Requests — Real User Flow

login-flow.js 
export default function () {
  // 1 — Login and get token
  const loginRes = http.post('/auth/login', payload, params);
  check(loginRes, { 'logged in': (r) => r.status === 200 });

  // 2 — Extract token from response
  const token = loginRes.json().accessToken;
  sleep(1);                      // user pauses

  // 3 — Use token in next request
  const res = http.get('/auth/me', {
    headers: { 'Authorization': `Bearer ${token}` },
  });
  check(res, { 'got profile': (r) => r.status === 200 });
}

Smoke Load Stress Spike

Each test type answers a different question about your system

Smoke

Smoke Test — Sanity Check

  • 1 virtual user
  • 30 seconds duration
  • Strict thresholds
  • All checks must pass
  • Run first, always
1 VU / 30s
smoke.test.js
export const options = {
  vus: 1,
  duration: '30s',
  thresholds: {
    http_req_failed:
      ['rate<0.01'],
    http_req_duration:
      ['p(95)<500'],
  },
};
If smoke fails — stop. Fix the issue before running any other test type.

Running Tests

CLI Commands

terminal 
# Run a test
k6 run smoke.test.js

# Override VUs and duration from CLI
k6 run --vus 10 --duration 60s smoke.test.js

# Run exact number of iterations
k6 run --vus 5 --iterations 50 smoke.test.js

# Save results to JSON / CSV
k6 run --out json=results/smoke.json smoke.test.js
k6 run --out csv=results/load.csv  load.test.js

Writing Checklist

What URL am I testing?
✓
What HTTP method? (GET / POST / PUT)
✓
Do I need headers or a body?
✓
What does a good response look like? → checks
✓
Set pass/fail thresholds
✓
Choose the right test shape (VUs / stages)
✓
Chain requests if needed (login → action)

Add sleep() to simulate real user pauses
